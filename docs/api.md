# API 约定

## 状态与返回值

| 当前状态 | Prepare | Commit / Enable | Disable | Destroy |
| --- | --- | --- | --- | --- |
| 未注册 | 创建，入口不变 | -1 | -1 | -1 |
| 已准备／已停用 | -1 | 激活 | 0，保持停用 | 取消并移除 |
| 已激活 | -1 | 0，保持激活 | 恢复原入口 | 恢复并移除 |

所有成功操作返回 0。重复启停仍会检查当前入口字节。
-1 表示参数、查找、构建、入口冲突或写入前失败；
-2 表示入口字节已经写入，但页权限还原或指令缓存同步失败。
遇到 -2 必须保持相关线程静止并处理系统错误，不能假定 hook 未安装。
注册项保留，避免仍生效的入口引用已经删除的状态。

Prepare 只在成功后写原函数输出。输出指针可为 NULL。
DobbyHook 把 prepare 与 commit 放在一次管理锁内，激活前已经
设置原函数指针；激活前失败会取消该次准备并清空输出。

地址必须指向可读、有效且足够长的函数指令；replacement 必须满足
原函数的调用约定。ARM Thumb 的最低位用于选择编码，查找和恢复
统一使用对齐后的入口地址。不能据此混用 ARM 与 Thumb 代码。

## 执行与资源

调用者负责暂停会进入目标、替换函数或 trampoline 的执行线程。
互斥锁串行化注册表与配置操作，不提供 stop-the-world，不保证
多字节补丁原子性。内存分配回调不能重入 hook 管理接口。

Disable 不释放 trampoline；Enable 不重新定位或分配。
Destroy 释放元数据、入口备份和临时补丁缓冲。代码 arena 的页及
其已分配块保留到进程结束；这不是可无限循环分配的可回收代码堆。
Destroy 后不得继续调用已取得的原函数指针，即便底层页仍然存在。

提交／恢复前比较预期入口字节，发现第三方修改则返回 -1，
不强行覆盖。恢复失败也不会先把 hook 从注册表中删除。

## 内存补丁

DobbyCodePatch 预检全部目标页，按系统实际页大小处理；
空地址、空缓冲、零长度、溢出和未映射跨度均拒绝写入。
每页保留其可观察到的原始权限，失败路径尝试还原已修改的权限。
调用方须保证源缓冲有效，并在整个操作期间保持映射不变。

Linux/Android 转译环境的 /proc/self/maps 可能只显示宿主权限。
已知的 hook 入口及内部 trampoline 写入会保留 guest 的逻辑执行权限；
通用 DobbyCodePatch 不猜测任意只读数据页是否实际存放 guest 代码。
直接在 NativeBridge 中修补可执行代码时，调用方须明确管理逻辑页权限。

## 指令范围

本库沿用上游的指令迁移器，不承诺覆盖每条 ISA 指令、任意短函数、
所有函数内部跳转、AVX/AVX-512、CET 或所有 PAC/BTI 场景。
已识别的不支持的 x86 迁移（例如 LOOP）会在修改入口前失败。
新增指令支持必须带实际 trampoline 执行回归，不能只验证解码文本。
